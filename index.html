Architecture Proposal

Discord AI Coding Agent 설계

Discord에서는 일반 AI처럼 대화하고, 실제 코딩 작업은 Synology NAS worker와 GitHub PR 흐름으로 처리하는 구조입니다. 모델 선택과 에이전트 선택을 분리하고, 위험한 변경은 승인 기반으로 실행합니다.

전체 구조

Discord
  ↓
Cloud Bot API
  ↓
Queue / DB
  ↑
Synology NAS Worker
  ↓
GitHub App
  ↓
GitHub Repo / PR / GitHub Actions

역할 분리

Cloud Bot

Discord 메시지를 받고 세션 상태, 승인 UI, 모델 설정, 작업 큐 등록을 담당합니다.

DiscordSessionApproval

Synology NAS Worker

GitHub repo를 임시 workspace에 clone하고, 코드 수정, 테스트, 빌드, branch push를 수행합니다.

DockerBuildTest

GitHub App

repo별 최소 권한으로 installation token을 발급하고 PR, checks, branch 작업을 수행합니다.

PRChecksPermissions

사용 방식

일반 대화

나:
my-org/my-repo에서 로그인 테스트 깨지는 거 봐줘

봇:
repo를 가져와서 실패 원인 확인하겠습니다.

봇:
수정 diff를 만들었습니다. PR로 올릴까요?

설정 명령

/repo my-org/my-repo
/model auto
/model strong
/model cheap
/agent auto
/agent claude-code
/agent codex
/budget 5

모델과 에이전트

/model은 판단과 답변 생성 모델을 고르고, /agent는 실제 코드를 수정하는 실행기를 고릅니다. 예를 들어 대화 판단은 GPT 계열로 하고, repo 수정은 Claude Code CLI나 Codex CLI로 맡길 수 있습니다.

작업 흐름

단계 처리 담당
1 Discord 메시지를 받아 의도와 repo context를 확인합니다. Cloud Bot
2 작업을 queue에 등록하고 세션 상태를 저장합니다. Cloud Bot / DB
3 NAS worker가 queue를 polling하고 repo를 임시 workspace에 clone합니다. NAS Worker
4 관련 파일 검색, AI agent 실행, diff 생성, 빠른 테스트를 수행합니다. NAS Worker / Agent
5 Discord에 diff와 테스트 결과를 보여주고 승인을 받습니다. Cloud Bot
6 승인 후 branch push, PR 생성, GitHub Actions 상태 감시를 수행합니다. NAS Worker / GitHub

승인 정책

자동 허용

  • repo clone
  • 파일 읽기
  • git status / diff
  • lint, test, build
  • Actions 상태 조회

승인 필요

  • 파일 수정 적용
  • commit / push
  • PR 생성
  • package install
  • workflow 파일 수정

강한 승인 필요

  • 파일 삭제
  • git history rewrite
  • secret 접근
  • 배포
  • main branch 직접 push

Synology NAS 배치

/volume1/ai-agent/
  workspaces/
    job-001/
    job-002/
  cache/
    npm/
    pnpm/
    pip/
  logs/

NAS는 외부 inbound 포트를 열지 않고 queue를 outbound polling합니다. 작업은 Docker 컨테이너 안에서 실행하고, 완료 후 workspace를 삭제하거나 짧게 보관합니다.

빌드와 테스트

NAS Worker

  • 관련 테스트
  • lint
  • typecheck
  • build smoke test

GitHub Actions

  • full test
  • full build
  • e2e
  • deploy preview

긴 세션 맥락 관리

Discord 스레드 전체를 매번 모델에 넣지 않습니다. 최근 메시지, running summary, pinned decisions, current task state, 관련 파일, 필요한 로그만 조립해서 모델에 전달합니다. 

Session State
  - recent messages
  - running summary
  - pinned decisions
  - current repo
  - current branch
  - task status
  - inspected files
  - proposed diff
  - test results

MVP 순서

1Discord bot 기본 대화
2/repo, /model, /agent 설정
3GitHub App 연동
4NAS worker polling
5repo clone + 파일 검색
6diff 생성 + Discord 승인 버튼
7branch push + PR 생성
8GitHub Actions 상태 조회
9Claude Code / Codex CLI agent 추가
10토큰, 비용, rate limit 기반 fallback 추가

이 문서는 Discord 자연어 코딩 에이전트를 Cloud Bot, Synology NAS Worker, GitHub PR 흐름으로 나누는 기준 설계안입니다.
